# รายละเอียดการพัฒนา Phase 2: Corporate Knowledge Base & Security Guardrails 🚀

---

## 📌 สรุปเป้าหมายภาพรวมของ Phase 2
เปลี่ยนจาก **"เว็บแปลภาษาไอที"** ไปเป็น **"AI ที่จำเอกสารและสถาปัตยกรรมของบริษัทได้ 100%"** 
ช่วยให้ AI สามารถ **วิเคราะห์ผลกระทบต่อระบบเดิม (Impact Analysis)** ได้อย่างแม่นยำ และมี **ระบบความปลอดภัยข้อมูลระดับองค์กร (Enterprise Security)**

---

## 📂 ส่วนที่ 1: ระบบอัปโหลดและประมวลผลเอกสารองค์กร (Document Ingestion Engine)

### 1.1 Multi-format Document Uploader (หน้าจออัปโหลดเอกสาร)
- **ฟีเจอร์:** พัฒนา UI ให้ทีมงานสามารถลากวาง (Drag & Drop) เอกสารโปรเจกต์เดิมขึ้นระบบได้
- **รองรับประเภทไฟล์:** `PDF`, `DOCX`, `Markdown (.md)`, `Swagger JSON / OpenAPI`, และ `PRD`
- **หน้าที่:** สกัดข้อความ (Text Extraction) ออกมาจากเอกสารทุกประเภทให้อยู่ในรูปแบบข้อความบริสุทธิ์

### 1.2 Text Chunker & Chunking Strategy (ระบบหั่นท่อนเอกสาร)
- **ฟีเจอร์:** ระบบหั่นเอกสารขนาดยาวออกเป็นชิ้นเล็กๆ (Text Chunks) ขนาดประมาณ 500-1,000 ตัวอักษร
- **หน้าที่:** ช่วยให้การค้นหาตำแหน่งข้อความเฉพาะเจาะจงในเอกสารหลายสิบหน้าทำได้แม่นยำที่สุด

---

## 🗄️ ส่วนที่ 2: ฐานข้อมูลเวกเตอร์และระบบค้นหาบริบท (Vector DB & RAG Retrieval)

### 2.1 Embedding Generation (การแปลงข้อความให้อยู่ในรูปเวกเตอร์)
- **ฟีเจอร์:** นำท่อนเอกสาร (Text Chunks) ไปผ่านโมเดล Text Embedding (เช่น `text-embedding-004` ของ Google หรือ `OpenAI Embedding`)
- **หน้าที่:** เปลี่ยนข้อความภาษาคนให้กลายเป็นพิกัดเวกเตอร์ตัวเลข เพื่อให้ระบบเข้าใจ **"ความหมายเชิงลึก"** ไม่ใช่แค่การค้นหาคำตรงตัว

### 2.2 Vector Database Setup (การติดตั้งฐานข้อมูลเวกเตอร์)
- **ฟีเจอร์:** ติดตั้งฐานข้อมูลประเภท Vector DB (เช่น **ChromaDB**, **Qdrant**, หรือ **Pinecone**)
- **หน้าที่:** จัดเก็บพิกัดเวกเตอร์เอกสารทั้งหมดขององค์กร เพื่อให้ค้นหาข้อมูลย้อนหลังได้ภายในเวลาไม่กี่มิลลิวินาที

### 2.3 RAG Retrieval Engine (ระบบดึงบริบทเอกสารเดิมมาร่วมตอบ)
- **ฟีเจอร์:** เมื่อผู้ใช้พิมพ์ความต้องการใหม่เข้ามา RAG Engine จะวิ่งไปค้นหาท่อนเอกสารเดิมที่เกี่ยวข้องที่สุด 3-5 ชิ้น 
- **หน้าที่:** นำเอกสารเดิมส่งต่อไปเป็นบริบทคู่กับคำถามให้ Gemini AI ประมวลผล

## 🧠 ส่วนที่ 3: ระบบวิเคราะห์ผลกระทบและประเมินงาน (Impact Analysis & Smart Estimation)

### 3.1 Legacy Module Impact Analyzer (AI วิเคราะห์ผลกระทบต่อระบบเดิม)
- **ฟีเจอร์:** AI จะระบุอย่างชัดเจนว่า ฟีเจอร์ใหม่ที่ลูกค้าขอ จะกระทบต่อ Module / Database Table ใดในระบบเดิมบ้าง
- **ตัวอย่างผลลัพธ์:** 
  > ⚠️ *ฟีเจอร์นี้จะกระทบกับโมดูล `PaymentService.py` และตาราง `orders` เดิมของบริษัท*

### 3.2 Code Base Refactoring & Effort Estimator (ประเมินเวลาปรับแก้โค้ดเดิม)
- **ฟีเจอร์:** AI ประเมิน Man-Days โดยบวกเวลาการทำ Refactoring โค้ดเดิมเข้าไปด้วย
- **ตัวอย่างผลลัพธ์:** 
  > ⏱️ *เขียนฟีเจอร์ใหม่ใช้ 3 วัน + ปรับปรุงโครงสร้างเดิม 2 วัน รวมเป็น 5 วันทำการ*

## 🛡️ ส่วนที่ 4: ระบบความปลอดภัยและการคุ้มครองข้อมูลลับ (Enterprise Security & Data Protection)

### 4.1 PII & Secret Sanitizer Layer (ระบบสแกนและ Mask ข้อมูลสำคัญ)
- **ฟีเจอร์:** ตรวจจับและเซนเซอร์ข้อมูลสำคัญอัตโนมัติ (Automated Data Masking) ก่อนส่งออกไปภายนอก
- **สิ่งที่ตรวจจับและ Mask:**
  - **API Keys / Passwords:** `sk_live_xxx` ➔ `[REDACTED_API_KEY]`
  - **ข้อมูลส่วนบุคคล (PII):** เบอร์โทร, เลขบัตรประชาชน, อีเมล ➔ `[REDACTED_PII]`
  - **ชื่อความลับองค์กร/ชื่อลูกค้า:** ➔ `[CLIENT_NAME]`

### 4.2 Data Privacy & Hybrid Routing Choice (การเลือกโหมดความปลอดภัย)
- **ฟีเจอร์:** สวิตช์เลือกโหมดการประมวลผลสำหรับลูกค้า B2B Enterprise
  - **Cloud Mode:** ประมวลผลผ่าน Google Gemini AI (ความเร็วสูง)
  - **On-Premise / Private Mode:** ประมวลผลผ่าน Local LLM (เช่น Ollama / Llama 3) ที่รันภายในเครื่ององค์กร 100% โดยไม่ต้องใช้อินเทอร์เน็ต
